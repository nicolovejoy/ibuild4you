# Owner chat + self-edit guard (#245) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Owners and builders can write into a brief's open conversation from the Conversations tab, with or without a reply from Sam, and can no longer edit their own membership into a tangle.

**Architecture:** The chat route already accepts a message from any member. It gains a `reply: false` mode (store the message, skip the model) that only builder-side roles may use. A new `ConversationComposer` sits under the transcript in the builder's Conversations tab. A shared self-edit check refuses, server-side, any invite, tier change, brief-role change or removal whose target is the caller, and the People panel stops offering those controls on your own row.

**Tech Stack:** Next.js App Router, Firestore Admin SDK, React Query, vitest (+ jsdom and Testing Library for components).

**Spec:** Agreed in chat on 2026-11-01 (no separate doc). Issue: https://github.com/nicolovejoy/ibuild4you/issues/245. The decisions:
1. A message box in the Conversations tab for owners and builders, on the open (active) conversation, posting as the viewer with their name tag.
2. A "Sam replies" checkbox next to Send, on by default and back on after each send. Off = a note: stored and shown in the chat, no model call; Sam sees it in history on the next turn.
3. You can't add yourself again, change your own access tier or brief role, or remove yourself on a brief.
4. The status strip's "Join the conversation" link stays, with its text moved to `lib/copy.ts`.

- Match the surrounding code's comment density and style (header comments with the issue number, `#245`).

## Review Focus

1. **A note with no reply sent by a maker.** A maker (or apprentice) who sends `reply: false` (hand-built request) must still get Sam's normal streamed reply. The flag is honoured only for builder-side roles. Test in Task 2.
2. **A note is the last message in the session.** `shouldKickoff` returns false when the last message is not the agent's, so a maker opening a session that ends in an owner note gets no greeting; their next message gets Sam's answer as usual. Accepted behaviour, not a bug; Task 3's component header comment says so in one line.
3. **Self-check on an admin with no member row.** An admin acting on another person's row must never be refused by the self check (compare target email to the caller's email, never role). Test in Task 1.
4. **Mixed-case or padded email in an invite.** `Nico@Me.com ` invited by `nico@me.com` is still self. Test in Task 1.
5. **Empty or whitespace note.** The composer's Send is disabled for whitespace-only text; the route already 400s on empty content. Test in Task 3.
